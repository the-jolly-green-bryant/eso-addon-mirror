Better Buffs v0.3.10
- Startup Auto relevance correction: initialize the canonical Effect Runtime before UI construction so Auto group-state queries cannot access uninitialized runtime tables.
- Added a defensive pre-initialization guard to HasAutoGroupState().

- Expanded Auto visibility from the Warmask proof-of-concept into registry-driven provider intelligence. Auto can now become relevant from equipped gear sets, slotted skills, or a live group effect.
- Added an event-driven local capability snapshot. Worn gear is refreshed from BAG_WORN equipment events; slotted abilities are refreshed from ESO action-slot events across primary, backup, and Werewolf hotbars. No recurring loadout scanner was added.
- Major Courage Auto now recognizes Ferocious Roar through its verified provider IDs (39113/42155/42156/42157) and the Werewolf hotbar. Spell Power Cure and Olorime are also registered as local gear providers.
- Group-effect relevance is now independent from local capability. A supported raid effect can appear in Auto when the canonical runtime confirms the group/boss effect is actually active, even when another player supplied it.
- Added registry provider metadata for current high-value raid effects including Major Force, Major Slayer, Major Courage, Minor Courage, Powerful Assault, Pillager, Major Vulnerability, Major/Minor Breach, Off Balance, Z'en, Alkosh, Elemental Catalyst, Martial Knowledge, Morag Tong, and supported Mythics.
- Hidden remains an absolute HUD override; Always remains permanently visible; Auto now resolves local provider capability OR registry-defined live group relevance.
- Runtime observation was separated from Auto presentation so a first application can make an Auto tile appear instead of being discarded before relevance is known.
- Provider-only state is cleared when the corresponding gear/skill capability disappears, preventing stale self-proc state from resurfacing after a later gear swap.
- Existing Warmask ownership/lifecycle, Aura reconciliation, Courage coverage reconciliation, Off Balance lifecycle, analytics, and scene management are unchanged.

Better Buffs v0.3.07

Better Buffs v0.3.05

- No additional EVENT_EFFECT_CHANGED or EVENT_COMBAT_EVENT owner was added.

Better Buffs v0.3.04

- Off Balance now uses the correct two-stage target lifecycle: active effect, then a 15-second target immunity cooldown only if that target survives the fade. Target death clears both immediately.
- Hostile debuff presentation now gives active bosses strict priority over previously cached trash targets. Existing trash state cannot take over a boss-fight tile.
- Reticle-target effects such as Mark of Hircine obey the same boss-priority rule during boss encounters.
- Encounter end now clears hostile target state without indiscriminately erasing real player/group buffs that are still active.
- Provider and recipient cooldown intelligence is preserved only according to registry ownership rules.
- Pillager READY is now affirmative: it does not glow READY until a real Pillager recipient event has established a provider in the current runtime.
- Elemental Catalyst is represented as one composite tile backed by Flame Weakness, Frost Weakness, and Shock Weakness child states. The stack badge represents active elemental weaknesses (0-3).
- Hostile target death clears target-owned cooldown state as well as active debuffs.
- No new tracker, cache, EVENT_COMBAT_EVENT owner, EVENT_EFFECT_CHANGED owner, or recurring update loop was added.
