Shopping List SL3 Format
========================

SL3 is the lightweight single-list exchange format used by Shopping List
0.18.5 and companion add-ons. It preserves enough information to create a
fresh shopping list with linked items and matching rules. It does not contain
purchase progress, history, archived lists, or settings; those belong to the
SLB1 full-backup format.

Code envelope
-------------

An SL3 code is:

    SL3: + base64url(payload)

The base64url alphabet is:

    ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_

Padding characters are omitted. Strings are stored as their raw UTF-8 bytes,
and every string length is a byte count. All integers are unsigned and
big-endian.

Primitive fields
----------------

- u8: one byte.
- u16: two bytes.
- u32: four bytes.
- string16: u16 byte length followed by that many bytes. Empty strings are
  encoded with a zero length and no following data.

Payload body
------------

    u8       format version; always 3
    string16 list name; 1-512 bytes
    string16 list note; 0-2000 bytes
    u8       recurring list: 0 no, 1 yes
    u16      item count; 0-500

Each item follows immediately:

    string16 item name; 1-512 bytes
    u32      desired quantity; 1-1,000,000
    string16 ESO item link; 0-2048 bytes
    string16 item note; 0-2000 bytes
    string16 matching set name; 0-512 bytes
    u32      matching set ID; 0 means absent
    u16      trait type plus 1; 0 means absent
    u8       quality mode: 0 any, 1 minimum, 2 exact
    u16      item quality plus 1; 0 means absent
    u8       level mode: 0 any, 1 exact
    u16      required level plus 1; 0 means absent
    u32      Champion Points plus 1; 0 means absent
    u32      maximum unit price; 0 means absent
    u8       quantity target: 0 buy more, 1 own total

A nonzero set ID requires a non-empty set name. Minimum or exact quality mode
requires a quality value. Exact level mode requires both level and Champion
Point values. A non-empty item-link field must be a complete ESO item link.

Checksum
--------

Append one u32 Adler-32 checksum after the complete payload body and before
base64url encoding. Use modulus 65521, initial A = 1 and B = 0, and return:

    (B * 65536) + A

The checksum covers the body beginning with the format-version byte and ending
with the final item's quantity-target field. It does not cover its own four
bytes or the SL3 prefix.

Compatibility
-------------

Shopping List continues to import SL1 and SL2 codes. Imported SL1 and SL2
quantities use Buy More behavior and import as non-recurring lists. New exports
use SL3. Companion add-ons
should generate SL3 and should not generate SLB1 backup data.
